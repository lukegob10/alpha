# Coding agent workflow tasks

These tasks exercise Alpha's real extension harness and its existing skills, Tickets, previewer, and scheduled tasks.
Use them when investigating user-visible regressions or comparing behavior with Codex CLI. The associated deterministic
tests provide contract evidence; scripted model decisions do not measure live coding quality, token savings, or speed.

Use exact VS Code **1.125.0**. For a live run, use a dedicated, signed-in Alpha-owned profile and record the exact model ID,
reasoning setting, source revision, fixture, approval configuration, initial workspace state, and provider retries. Keep
Alpha's execution protections in place. Run failure injection only in disposable fixtures.

| Task                                                 | User workflow                                                                                                                                                                  | Observable acceptance                                                                                                                                                                                                  |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recover an unavailable source path                   | Ask the agent to inspect a file through native `exec_command`. The scripted first command reads a missing sibling; the next reads the correct file.                            | Exit code 1 and missing-file output survive in subsequent requests and saved history. The corrected read exits 0, each call has one result, and ordinary assistant text completes once without asking for path repair. |
| Stop while MCP reads await approval                  | Request two independent MCP reads. Approve the first and stop the task while the second approval is pending.                                                                   | Neither tool dispatches. Both calls receive cancellation results. The journal records no started effect for either read, so recovery does not describe an undispatched read as having an unknown result.               |
| Resume interleaved reasoning                         | Script an OpenAI response containing text, encrypted reasoning, a file-read call, another encrypted reasoning item, and more text. Save and reload before the next request.    | Streaming and nonstreaming responses replay all reasoning, text, call, and result items in their original order. Opaque bytes and summaries survive once each.                                                         |
| Save a scheduled review result after a storage fault | Run a scheduled repository review in Plan. Inject one failure while saving the terminal result, then allow the existing scheduler tick to run.                                 | The original result becomes durable without rerunning the task. Completion and abort delivery are idempotent; the first terminal outcome wins. No rejected event-listener promise escapes.                             |
| Edit the selected skill variant                      | Create generic and Code variants with the same skill name. Open and update the Code row in skill settings.                                                                     | The selected file opens and only that file changes. An ambiguous older request cannot overwrite a sibling. Built-in skills remain read-only.                                                                           |
| Make a directory-scoped skill available in Any mode  | Create a skill under a Code-specific skill directory. Select Any mode in settings and rediscover the catalog.                                                                  | The skill is available in both Code and Plan. Directory defaults cannot silently restore its old restriction.                                                                                                          |
| Delegate a bounded coding change                     | Ask for independent investigations, then authorize fixes in separate files. Cancel the parent while a child is running; separately test a normal successful child integration. | Child authority never exceeds the parent's captured policy or workspace. Cancellation propagates, every child reaches a terminal state, and the parent verifies changes before completing.                             |
| Review, fix, validate, then continue                 | In a disposable repository, review a seeded bug, implement a fix with a regression test, validate it, make an explicitly requested local commit, and send a follow-up change.  | Earlier work and external edits survive. Failed checks are reported truthfully. The follow-up continues the same task and creates no duplicate commit or synthetic completion request.                                 |
| Complete a Ticket through a skill                    | Ask Alpha to implement one scoped Ticket using an available project skill and run its required checks.                                                                         | Ticket state reflects verified work; loading a skill does not widen write or command authority. Retry and cancellation preserve the Ticket's history.                                                                  |
| Iterate on an HTML preview                           | Ask for an HTML document, inspect its preview, then request a narrow revision after an external file edit.                                                                     | The preview follows the current saved file, external changes survive, and closing or reopening the preview does not restart the task or leak resources.                                                                |

The Astra follow-up adds these failure-injection workflows to the same acceptance catalog:

| Task                                                 | User workflow                                                                                                                                                                                                                                        | Observable acceptance                                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recover a delayed command failure                    | Start a command that yields a session, then let it exit nonzero before or while `write_stdin` waits. Compare with the same immediate failure.                                                                                                        | Both receipts retain the process error, output and exit code. The transaction status is consistent, one terminal result is saved, and the settled session is released.                                                                                                                                  |
| Read truncated command output                        | Run ordinary commands and audited Git/rg reads whose full output is retained; follow each actual retrieval instruction. Also read retained numeric and UUID artifacts in Plan.                                                                       | The instruction names `write_stdin` and its returned `artifact_id`. Complete and streamed parsing preserve that read branch, and the reader returns bounded task-owned output for both historical filename formats. Plan rejects session control, mixed targets and terminal input.                     |
| Recover after a queue acknowledgment storage failure | Save a tool result and attached human guidance, inject one pending-queue deletion failure, then abort or continue the task. Repeat with a durable follow-up instruction; separately fail the transcript write itself.                                | Successful transcript content is saved once, including guidance and the original error status. A committed follow-up admission resolves before independent queue deletion. Deletion can retry; failed transcript writes retain unsaved content.                                                         |
| Continue an Anthropic thinking response              | Return multiple separately signed thinking blocks, a signed empty block, redacted thinking and a tool call. Save, reload and continue after the tool result.                                                                                         | The next provider request retains each signed or redacted block unchanged and in order. Partial or cancelled reasoning cannot inherit another block's signature; visible reasoning is not duplicated.                                                                                                   |
| Account for cumulative streamed usage                | Script Anthropic output totals of 1, then 5, then 9, and run the next request separately.                                                                                                                                                            | The additive harness records a total of 9 for the first request. Request-local counters reset for the next response; usage is not counted repeatedly.                                                                                                                                                   |
| Start schedules while notifications remain open      | Run prompt and command schedules with Before run notifications, leave a toast undismissed, and queue another schedule. Repeat with a rejected toast promise.                                                                                         | Informational presentation does not block either schedule. Failures are contained, disposal releases owned work, and the command approval modal still governs execution.                                                                                                                                |
| Preserve root budgets after closing children         | Complete a child that consumes most of a frozen root token or cost budget, close it, then attempt another delegation before and after provider reload.                                                                                               | Closing releases runtime capacity while retaining spent tokens and cost. The new delegation is rejected at the original limit, and older tombstones remain readable.                                                                                                                                    |
| Retry a failed child follow-up admission             | Complete a child, inject a mailbox or parent-group publication failure while starting a follow-up, then retry after storage recovers.                                                                                                                | The failed admission has an explicit retryable state with no phantom running child. The retry launches one runner and delivers the instruction once without widening authority.                                                                                                                         |
| Keep frozen root limits after child history deletion | Complete a child exactly at a frozen root limit, close it, delete its history through the supported UI operation, raise or unset current limits, then reload and delegate again.                                                                     | The root still rejects at the original captured token or cost limit. Preserved spend and frozen orchestration survive independently of the deleted transcript.                                                                                                                                          |
| Read all output after a yielded command finishes     | Let a command session finish with a log larger than one receipt; poll with normal and small positive output budgets.                                                                                                                                 | The receipt preserves the exit code, reports omitted output, and identifies a retained reader handle. Further bounded polls recover the tail before the handle is released.                                                                                                                             |
| Deny or cancel a custom external tool                | Enable a harmless custom callback in Ask mode. Deny it, approve it, cancel during approval, and fail effect-start persistence separately.                                                                                                            | Denial, cancellation and admission failure prevent the callback. Approved order is decision, durable effect start, then callback. The callback uses captured mode and can observe the supplied cancellation signal.                                                                                     |
| Cancel or steer while preparing a resumed chat       | Save a tool result and human guidance, reopen the chat, pause new-input preparation at a controlled boundary, and cancel before commit. Separately steer during preparation with one missing historical result.                                      | The prior tool pair, guidance, origins and receipt metadata remain durable. Retry appends new input once without deleting or replaying committed evidence. A committed repair cannot roll back after steering; every admission callback settles once and a rejected callback releases the pending flag. |
| Rewind a chat with retained command artifacts        | Save numeric and audited-read UUID command logs, rewind a later message, and read the retained logs. Repeat with a failed UI or API transcript save, and produce new output after the rewind snapshot.                                               | Output referenced by either retained transcript remains readable. Selective cleanup runs only after confirmed saves and removes only known pre-rewind artifacts whose references were removed. New output and unrelated files survive; failed saves cannot delete committed evidence.                   |
| Revoke or grant task creation during steering        | Resume an interrupted creation request with a revocation; repeat during input preparation, post-save pacing and manual-retry publication. Also steer a safe request with a fresh grant, or steer agent/hook guidance with an image-only human input. | The latest human instruction governs both the native catalog and host admission. Each input retains its own origin, hook and queue receipts. Committed input is not replayed during retry; agent/hook text cannot acquire human authorization. Reload and retained-history paths agree.                 |

The new unavailable-path host scenario is included in `core-loop-boundaries.test.ts`, alongside continuation, malformed
call, and incomplete-response scenarios. After building the extension, run the existing host runner:

```sh
pnpm bundle
pnpm --dir apps/vscode-e2e compile
pnpm --dir apps/vscode-e2e exec node ./out/runTest.js --vscode-version 1.125.0 --provider scripted --require-all-tests --file core-loop-boundaries.test
```

The Astra command-artifact host scenario follows the retrieval instruction emitted by a real command, searches its
retained tail, and reads a bounded byte range through `write_stdin`. A second scenario reads a task-owned UUID artifact in Plan
and confirms that the advertised schema exposes no terminal session controls. Plan's fixture seeds the artifact directly;
it does not execute a command to create it. Both scenarios check saved tool pairs and exactly one ordinary-text completion.

```sh
pnpm --dir apps/vscode-e2e exec node ./out/runTest.js --vscode-version 1.125.0 --provider scripted --require-all-tests --file command-artifact-workflow.astra.test
```

The existing exact-host smoke gate covers Alpha's Tickets, compaction, approval boundaries, asynchronous user input,
image inspection, and VS Code Language Model adapter:

```sh
pnpm --filter @alpha-code/vscode-e2e test:smoke:1250
```

Managed-agent changes also require the existing certification gate:

```sh
pnpm certify:managed-agents:automated
```

For the longer coding and workflow tasks, use the existing scenario runner and development/reliability catalogs in
[`apps/vscode-e2e/src/scenarios/`](../../apps/vscode-e2e/src/scenarios/). This task list adds no separate execution engine
or benchmark admission. Do not regenerate pinned Frontier fixtures or historical reports to incorporate these tasks.
