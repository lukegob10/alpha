# Subagent budget and handoff investigation (2026-09-28)

## Reproduction

The local task `01a0e118-ed81-72bc-9673-5a50ead5b671` asked Alpha to launch two test subagents. Both inherited the previous default cumulative limits of 16,000 input and 4,000 output tokens. Each child began with a roughly 7,100-token input request. After three model requests, the children had used 22,084 and 21,977 input tokens, so Alpha stopped both with `input_token_limit` before either test suite finished. The default budget allowed only two complete model steps at this prompt size.

The parent trace also separates this failure from the observed handoff time. The first model response took 8.5 seconds. The two launch approvals consumed 23.4 seconds, including about 21 seconds waiting for the first manual approval. The spawn tool returned at 31.9 seconds. The first child turn began about 10 seconds later. The two child turns stopped at 61.5 and 63.4 seconds; their durable terminal results became available at 67.1 and 71.5 seconds. The parent's pending `wait_agent` returned with the first result at 67.1 seconds. These are timestamps from one manual run, not a controlled speed comparison. The parent used GPT 6 Luna at Max effort, and the user sent a stop request during the run.

## Correction

New tasks use cumulative per-child defaults of 250,000 input and 16,000 output tokens. This matches the limits used by the exact-host managed-agent acceptance fixtures and leaves explicit custom limits intact. A one-time migration clears the exact old 16,000/4,000 saved pair, since previous settings pages persisted default values as though they were user overrides. It records a migration state so an interrupted write resumes safely. Existing child manifests retain their frozen limits. A deliberately customized pair remains unchanged; an explicit choice equal to both old defaults is indistinguishable from a saved default and will migrate.

This fixes the demonstrated premature stop. It does not prove a latency gain or full Codex CLI parity. At upstream Codex commit [`69043f05`](https://github.com/openai/codex/blob/69043f05c4c5e2afd0cec7aaf0dbc8166f7d63b5/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs), retrieved 2026-09-28, the spawn arguments include the task, fork mode, model, and reasoning effort, with no per-child cumulative input/output ceiling. Codex's [token-budget session code](https://github.com/openai/codex/blob/69043f05c4c5e2afd0cec7aaf0dbc8166f7d63b5/codex-rs/core/src/session/token_budget.rs) concerns context guidance and compaction. Alpha retains configurable cumulative ceilings as an intentional extension policy. The [official OpenAI Subagents documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) describes independent agent threads for parallel tests and consolidated parent results.

The roughly 10-second child start interval and the 5.6-to-8.1-second child-turn-to-durable-result intervals need a controlled before/after workload before attributing them to a local bottleneck. The test subagents were Workers, so they created and captured isolated Git worktrees even though the requested tests made no source edits. That path includes several Git commands and worktree cleanup; it is a plausible source of fixed overhead, but this trace does not time each stage separately.
