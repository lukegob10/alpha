## Implementation and investigation history

The existing extension-host and React tests do not by themselves prove rendered webview interaction. `webview-ui/vitest.config.ts` uses jsdom and mocked VS Code messaging; `diff-preview-ownership.test.ts` invokes the real bundled diff provider, but does not click a rendered Apply button. Keep these useful contracts distinct from actual renderer evidence.

Read-only investigation on 2026-09-18 found no existing Playwright, Puppeteer, Selenium, or CDP adapter in the evaluator runner. Native computer-use is disabled in this session. The cached exact host is VS Code 1.122.1, commit `8761a5560cfd65fdd19ce7e2bd18dab5c0a4d84e`, declaring Electron 39.8.8. Its compiled main/CLI support the renderer debugging switch; its webview prelude creates a same-origin nested `iframe#active-frame` containing the extension DOM.

The bounded spike extends the existing host runner with a programmatic `rendererDebuggingPort: 0` option, restricted to the scripted `rendered-ui-probe.test` and `managed-agents.acceptance.test` fixtures and an owned profile. It is not a CLI/global configuration default. Chromium chooses the port; the controller reads `DevToolsActivePort` only from that newly owned profile. `ui/cdp.ts` uses Node's native WebSocket, permits only loopback endpoints, limits pending commands and response sizes, and clears command timers on close. No browser automation dependency or parallel extension runtime is introduced.
