# Rich documents

Alpha includes a Rich documents skill for substantial specs, reviews, and quantitative reports. Ask for an HTML document or invoke `/rich-documents`. For short answers or ordinary code changes, continue using chat. Ask for plain text or Markdown whenever that is the output you want.

The response includes a takeaway and an **Open document** link. A newly delivered document in the visible task opens automatically in the active editor group, preserving chat focus. The link remains available to reopen it. Background tasks and restored history do not open tabs; revisions update the same preview. Use the evidence links, table sorting/filtering, or chart/table view to inspect the content. The underlying HTML remains a normal workspace file: edit it with your usual source tools, and refresh or reopen the same preview. Keep the file at the same path to preserve earlier links. Previously saved links require their workspace folder to be open. The preview explains unsupported content or unavailable files so you can correct the source or reopen the folder.

Rich documents use Alpha's built-in HTML previewer exclusively. The skill must not open or validate them through browser tools, an external browser, or a localhost server. `alpha-document://open` is an Alpha chat action, not a website URL. When direct preview inspection is unavailable, the skill validates the source and delivers the link, reporting that visual verification was unavailable. A failed preview stays in the document repair flow without a browser fallback.

The shared kit uses a wider responsive layout, rounded tables and cards, compact metric summaries, and labeled status badges. Green means verified health, amber means attention, and red means risk; color always accompanies text. Existing version-1 documents receive the shared styling when reopened. New documents can use the expanded components described in the packaged reference.

In **Settings → Skills → Built-in**, inspect the bundled instructions or toggle **Enabled**, then **Save**. Unsaved edits remain local to Settings. Disabling removes the built-in from future eligible skill discovery without deleting documents, user skills, or instructions already captured by an in-flight task.

To use your own guidance, create a skill named `rich-documents` in the workspace's `.alpha/skills/rich-documents/SKILL.md`, or in your personal `~/.alpha/skills/rich-documents/SKILL.md`. Workspace overrides win over personal overrides, which win over the built-in. Existing `.agents` directories and mode restrictions continue to work; Alpha-specific guidance wins at the same source and mode. An override applies only in its eligible modes. If you remove an override, the next eligible source is used; a disabled built-in remains disabled. Relative references resolve from your selected skill's directory. Extension updates do not overwrite your skill or template files.

Bundled examples and references ship inside Alpha. They require no project setup, plugin installation, network connection, or package download. Source evidence and external links still refer to their actual files or websites; unavailable evidence is not fabricated.
