# Testing and evaluation evidence hardening

Reviewed on 2026-10-02 against repository commit `98634bb7a506dd2b1c3e38c7cf5bf8010bf1df3a`.
The working mode is operational hardening: improve the existing harness and its evidence boundaries, preserve the
extension as the system under test, and make unsupported claims visible. This is not a claim that every repository
surface has exhaustive coverage or that production monitoring has been deployed.

## Evidence owners

- `scripts/harness/` selects existing package runners and joins their receipts. Its matrix distinguishes test discovery
  from current execution. See [the evidence runbook](harness-evidence.md) for the surface matrix, 15 evaluation layers,
  prerequisites, receipt freshness, and CI commands.
- `packages/evals/src/grading/` owns deterministic criterion validation, result aggregation and calibration controls.
  `benchmark/graderBroker.ts` carries private grading requests to the existing trusted controller.
- `apps/vscode-e2e/` runs the actual extension in exact VS Code **1.125.0**. Scripted provider campaigns exercise real
  tools and independently inspect repository effects. Their outcome evidence is separate from live model capability.
- `src/core/agent/` owns terminal lifecycle behavior and durable runtime events. Unit fault trajectories complement
  actual extension-host tests; neither substitutes for the other.

## Fixed failure modes

| Area                     | Previous failure                                                                                | Current contract                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Grader configuration     | No graders or empty assertions could pass                                                       | Reject missing, empty and malformed criteria before execution                                                               |
| Plugin results           | Plugins could return skipped/unknown status, missing evidence, or altered gate identity         | Validate result identity, version, policy, status, diagnostics and SHA-256 evidence metadata                                |
| Aggregation and controls | A claimed decision could pass calibration without underlying results                            | Recompute the decision from validated results; empty or invalid evidence is a grader error                                  |
| Command graders          | Missing exit codes were outcome failures; timeout exceptions discarded captured output metadata | Distinguish infrastructure/grader errors and preserve captured diagnostics and evidence                                     |
| Usage and trace grading  | Missing cost became zero; an empty trace satisfied absence or upper-bound checks                | Require observed finite nonnegative cost and a nonempty valid ordered trace; report unavailable metrics explicitly          |
| Trusted broker           | Old response files and incomplete result envelopes were accepted                                | Bind receipts to unique requests, validate attempts/artifacts/results, reject unbound or contradictory receipts             |
| Diff grading             | Controller trusted agent paths; commits, ignores and filename parsing could hide changes        | Capture a starting commit; read host working/index diffs and all untracked paths with NUL records; reject incomplete output |
| Terminal lifecycle       | Completion callbacks could hide failed or incomplete terminal states                            | Preserve terminal callback states and the original step failure across both adapters                                        |
| Diagnostic persistence   | Non-Bearer authorization credentials could survive event redaction                              | Share credential-text redaction across the runtime event log and lifecycle journal                                          |
| Host acceptance          | A partially skipped gate or missing build identity could appear successful                      | Require selected hard-gate tests and comparable captured build/workload evidence                                            |

The evaluator compatibility change is intentional: formerly accepted empty graders, malformed results, missing
telemetry and unbound broker response files no longer qualify as a pass. Existing task histories are not migrated or
deleted. Broker callers retain their request API; current peers add a request ID to the wire receipt. Old unbound
ephemeral broker files fail closed and must be regenerated by a current run. The request ID correlates a response; it
does not replace the existing trusted-controller filesystem and execution boundary.

Broker envelopes are limited to 8 MiB, read through a bounded buffer, and reject size changes or linked envelope files.
Malformed JSON diagnostics do not include payload fragments. This limit applies to the control envelope; captured tool
output remains in the existing bounded artifact store.

Filesystem and static-analysis graders share a contained read that rejects links/junctions below the workspace and
detects file changes during capture. Unknown access errors cannot prove absence. Usage limits count legacy command
verification events as tool activity while avoiding the duplicate verification annotations in canonical traces.
Hidden command graders resolve both roots before checking disjointness, so a workspace junction cannot expose private
grading assets. Their working directory and workspace environment value use those resolved paths.

Git evidence collection rejects `skip-worktree` and `assume-unchanged` entries inside the graded workspace: both flags
can conceal a tracked edit from ordinary diffs. It reports unavailable evidence instead of trusting an empty change set,
and never clears flags or rewrites the workload index. Flags outside the task workspace do not affect its grade. This
intentionally excludes sparse or manually suppressed task workspaces until they have a trustworthy capture contract.
The diagnostic redactor also preserves protection for multiline assignments and quoted authorization values; persistence
regressions inspect both journals, snapshots and replay while checking that provider data remains unchanged.

Concurrent local ticket launches for the same project, ticket and revision now join one pending launch. The existing
cross-host advisory lock remains in place. Controlled contention tests cover the launch, independent returned values and
retry after failure; the [fault-contract note](harness-fault-security-contracts.md) records the adjacent suite fixes.

Actual smoke validation exposed an ownership-evidence gap in disposable hosts: all 40 tests passed, but their receipts
lacked process-ancestry proof and were rejected. Disposable and persistent runner-managed hosts now use the same existing
ancestry check before exporting verified ownership. Old receipts remain invalid; passing test counts cannot upgrade
missing ownership evidence.

The first scripted outcome campaign also caught active fixture drift: development scenarios called retired file tools,
command traces missed canonical `exec_command` arguments, and lifecycle capture dropped `tool_effect_started` events.
Scripted phases must use the advertised native catalog and the workflow's actual policy surface. A regression drains
each phase through ordinary final text and checks canonical names, executable permission, argument schemas and command
allowlists against those owners. Independent repository assertions still decide whether the workflow succeeded; valid
fixture calls alone do not establish an outcome. Capture retains the known effect-start event and hashed call identity
without retaining private command arguments or relaxing sequence validation.

Saved campaign reports use native relative paths. Admission normalizes separators only, then requires the exact
`attempt-XXXX/evidence-index.json` binding and emits portable references. Absolute paths, traversal, dot segments,
duplicate separators and references to another attempt remain invalid. This preserves existing Windows reports without
widening the evidence path boundary.

Outcome re-admission requires the scenario-specific independent repository and verification assertions in addition to
generic lifecycle checks. Their required names belong beside the existing verifiers, whose fixture tests check that
actual results contain them. Removing one required assertion cannot produce a pass even if the shortened workflow JSON
has a consistent byte count and digest. These hashes bind evidence contents; they are not signatures from an independent
trust authority.

A completed physical turn can hand off work that remains semantically blocked or unverified. The unavailable-verifier
scenario requires the failed verification receipt, missing prerequisite, unchanged repository, explicit unverified
handoff and actual terminal lifecycle evidence together. It cannot establish that requested verification passed, and
absence of a retired completion tool is not evidence of a blocked outcome. Historical tool records remain readable.

Required commands must have fresh, completed exit-zero receipts in recovery phases as well. Expected nonzero search or
verification attempts have separate recovery assertions and do not waive successful Git status checks. Actual host
capture also establishes that Alpha promotes the final ordinary assistant text to `completion_result`; the unverified
handoff check accepts that projection only with the same complete report, phase and terminal lifecycle evidence.

## Sources and behavioral alignment

The core review inspected current [Codex CLI source](https://github.com/openai/codex/tree/c39bfa4c8ff9a57c46a9d3766676d6435e262691)
at commit `c39bfa4c8ff9a57c46a9d3766676d6435e262691` (retrieved 2026-10-02), including
`codex-rs/core/src/tools/parallel.rs` and `codex-rs/core/src/session/turn.rs`. Captured tool context, structured terminal
receipts and waiting for tool completion are reference behavior. Alpha retains its TypeScript execution kernel, VS Code
adapters and existing permission model. No upstream runtime or prompts are copied.

Git filename parsing follows the official [diff contract](https://git-scm.com/docs/git-diff) and
[ls-files contract](https://git-scm.com/docs/git-ls-files), retrieved 2026-10-02. NUL-delimited records preserve unusual
filenames. Comparing the captured starting commit to both the working tree and index retains committed and staged
changes; disabling rename detection retains both endpoints. Paths are relative to the task workspace. Untracked files
are collected without ignore exclusions so `.gitignore` cannot narrow grading authority. Fixture authors must explicitly
allow expected generated outputs in restrictive diff policies. No new benchmark dataset, dependency, external grader
service or production rollout is introduced.
The [update-index contract](https://git-scm.com/docs/git-update-index), retrieved 2026-10-02, explains the suppression flags;
`ls-files -v -z` exposes their tags without changing the index or losing unusual filenames.

The host review used the official [VS Code extension testing guide](https://code.visualstudio.com/api/working-with-extensions/testing-extension)
and [Node 24.14.1 filesystem contracts](https://github.com/nodejs/node/blob/v24.14.1/doc/api/fs.md), retrieved 2026-10-02.
Alpha's required gates deliberately require observed nonpending test counts beyond a failures-only runner result.
Contained grading reads inspect link components, verify file identity around capture, and close file handles explicitly.
The Codex review also checked `protocol/src/models.rs` tool-result serialization tests: known empty strings remain valid
payloads, while missing payloads are not evidence of a completed transaction. Persisted history readers are unchanged.

## Validation and baseline interpretation

Use the [evidence runbook](harness-evidence.md) to run lanes and produce the current matrix. Focused evaluator checks:

```sh
pnpm --filter @alpha-code/evals test:unit src/grading/__tests__/failClosed.spec.ts src/grading/__tests__/grading.spec.ts src/grading/__tests__/controls.spec.ts src/benchmark/__tests__/graderBroker.spec.ts src/cli/__tests__/processTask.lifecycle.spec.ts
pnpm --filter @alpha-code/evals check-types
pnpm --filter @alpha-code/evals lint
pnpm test:evals:offline
pnpm --filter @alpha-code/vscode-e2e test:smoke:1250
```

Tests first reproduced the grader/broker false passes and the lifecycle/redaction failures. After fixes, the full offline
suite also exercises reference, alternative-correct, broken and no-op controls, repeated calibration, reconstruction,
and serial/concurrent certification. These repetitions establish deterministic grading behavior; they do not establish
live-model success rates or a speed improvement.

The initial clean Windows checkout failed five offline tests because some content-addressed fixture and migration
worktree files retained CRLF bytes despite their canonical committed content. The committed migration bytes matched
every released hash. Only byte differences proven to be line endings were restored from the same commit; lock files,
released digests and fixture semantics were not changed. Existing `.gitattributes` remains authoritative. A future
digest failure must be investigated as evidence corruption, never repaired by blindly regenerating expected hashes.

## Closure ledger and limits

- **Fixed now:** the reproducible evidence, grading, lifecycle and diagnostic failures above, with focused regressions
  and integration into the existing runner/reporting paths.
- **Flagged for follow-up:** matrix cells with no discovered evidence; additional workload breadth and statistically
  powered live repetitions must be prioritized from those gaps rather than inferred from test counts.
  Release gates validate the source/build before packaging and archive contents afterward. Installed-VSIX behavior and
  identity between the tested bundle and the production bundle rebuilt by prepublish remain separate unverified scope.
- **Not verified without prerequisites:** live Copilot requires a current successful preflight, exact model identity,
  approved request budget and a signed-in Alpha-owned 1.125.0 profile. Retained old preflights are historical evidence.
  PostgreSQL/Redis integration requires dedicated configured service URLs; the local readiness probe reported both
  missing. Container coverage has its own infrastructure lane and is not required for offline verification.
- **Out of scope:** a production rollout, real canary traffic, randomized A/B deployment and continuous production
  monitoring. Layers 11–14 cannot be credited with production evidence from synthetic replay or local tests.

Machine-readable run receipts and the current evidence matrix live under `artifacts/harness/`. The completion report
must identify exactly which commands ran, their outcomes and any remaining prerequisites; this design note is not a
substitute for those receipts.
