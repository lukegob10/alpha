## Material gaps

### P2 — Public history merges a cancelled turn into a later completed turn

**Trigger:** a request ends after commentary/cancellation, then a new human request completes. `partitionTurns` only starts a new partition when the preceding assistant satisfied `isFinalResponse` (`ThreadHistory.ts:88–102`). It ignores a persisted cancelled/failed response outcome as a terminal boundary. `readIndependentThread` supplies only the latest task lifecycle (`AlphaProvider.ts:6001–6019`), so earlier journal terminals cannot repair the projection. The output loses the interrupted turn and reports one completed turn containing both requests. This affects the live `read_thread` surface and its pagination, not the underlying durable transcript.

**Executed reproduction:** bundled the actual `ThreadHistory.ts` in memory with the installed esbuild and invoked `buildThreadReadResult` on this valid transcript, with `status: { type: "idle" }`, `lastTurnStatus: "completed"`, and `turnLimit: 10`:

```ts
;[
	{ role: "user", input_origin: "human", content: "First request", ts: 1 },
	{
		role: "assistant",
		phase: "commentary",
		content: "Working on first request",
		agentResponseOutcome: { status: "cancelled" },
		ts: 2,
	},
	{ role: "user", input_origin: "human", content: "Second request after interruption", ts: 3 },
	{ role: "assistant", phase: "final_answer", content: "Second request done", ts: 4 },
]
```

Actual: `actualTurnCount: 1`, `actualStatuses: ["completed"]`, with both human messages in that turn. Upstream's equivalent lifecycle regression explicitly expects two turns and an interrupted first turn (`thread_history.rs:2829–2906`).

**Smallest robust fix:** make the public reader project persisted lifecycle turn boundaries/terminal outcomes and attach transcript items using durable turn identity; keep a documented legacy fallback. Do not treat every human message as a new turn because steering belongs within a running turn. **Regression:** cancelled and failed earlier turns followed by a completed request must remain separate and retain status through cold read, pagination and replay; mid-turn steering must stay in its current turn.

### P2 capability gap — Forks cannot retain committed evidence from an unfinished turn

**Trigger:** fork a running source, including the first turn. `forkTaskHistory(..., { active: true })` copies only host-confirmed completed turns (`ThreadHistory.ts:230–253`); a first active turn intentionally yields empty inherited history (`ThreadHistory.spec.ts:216`). Current Codex's app-server fork uses `ForkSnapshot::Interrupted` (`thread_processor.rs:5585`), retaining committed source history and appending the same interrupt boundary as a real interruption (`thread_manager.rs:2772–2791`).

This is an intentional conservative Alpha implementation, supported by tests, not silent corruption. It is still a meaningful convergence gap when the user expects a fork to carry the investigation evidence already collected in the current turn.

**Minimal extension:** introduce an explicit snapshot policy at the existing fork boundary. Preserve the current prefix option; add an interrupted snapshot that drains accepted transcript writes, copies committed call/result pairs, closes unresolved calls truthfully and marks the copied turn interrupted. Do not inherit live producers, goals, delivery receipts or permissions. **Regression:** active first-turn fork retains committed user/read/result evidence and a terminal interruption, leaves the source running, never reruns uncertain effects, and survives reload without an orphaned call.
