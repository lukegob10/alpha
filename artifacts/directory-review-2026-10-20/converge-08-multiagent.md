## Material remaining gaps

1. **P2 — Cold nested followups require manually reopening an intermediate parent.** After root reload or runtime eviction, a stopped grandchild remains visible but root `followup_task` rejects it when its immediate parent has no live/retained runtime. The explicit rejection is `src/core/webview/AlphaProvider.ts:10833-10840`, and the behavior is intentionally regression-tested at `AlphaProvider.subagents.spec.ts:4247-4276`. Codex can load the registered target directly without loading the intervening parent (`core/src/agent/control/api.rs:140-152`; grandchild tests `core/src/agent/control_tests.rs:1673-1678,1790-1825`). Minimal convergence change: use the immediate parent's durable frozen manifest and identity to reconstruct the bounded owner, or a focused ownership adapter, without using new live settings or widening scope. Regression: root reload, intermediate owner unloaded, followup of grandchild succeeds under original approval/scope/budget; no duplicate run; cancellation still reaches it. This is an ergonomics/recovery limitation, not evidence of data loss.

2. **P2 — Nested names and addressing are flatter than Codex.** Two different child branches cannot both name a nested agent `review` because `prepareSubagentGroup` reserves nicknames across the entire root (`AlphaProvider.ts:8198-8212`; `SubagentNicknameRegistry.ts:103-117`). Codex identifies names relative to their parent (`protocol/src/agent_path.rs:53-71`) and accepts nested relative references; Alpha accepts bare unique nicknames, IDs or absolute canonical paths, but its target schema rejects `branch/review`. Alpha also converts underscore names into hyphen path segments (`AgentControlStore.ts:3825-3834`), while Codex preserves underscores (`protocol/src/agent_path.rs:122-140`). Minimal change: reserve explicit task names per immediate parent, retain display-nickname uniqueness separately if desired, and resolve relative targets against the captured caller path. Preserve old canonical paths as aliases rather than rewriting persisted identities. Regression: two branches each spawn `review`; `review` resolves locally; `branch/review` resolves from root; canonical/ID access and legacy paths still work; out-of-tree controls remain denied.

## Intentional divergences and retained extension behavior

- Alpha's host-enforced role, workspace, approval, depth, concurrency and budget ceilings remain stricter than some upstream V2 paths. Upstream even tests V2 ignoring configured max depth (`core/src/tools/handlers/multi_agents_tests.rs:2485`). These ceilings implement Alpha's declared safety contract and should stay.
- Worker worktrees, quarantined/apply-reviewed changes, parent verification obligations and the native Alpha tool surface are retained additions. They are not convergence deductions.
- Alpha supports actual numeric `fork_turns` tail selection (`SubagentContextCapture.ts:693-698`); current upstream accepts numeric legacy values but treats them as a full fork (`multi_agents_v2/spawn.rs:231-234`). Defaults `all` and explicit `none` align. Treat tail selection as an explicit existing extension, not an accidental claim that numeric semantics match.
- Alpha passive send leaves stopped recipients dormant and retains durable mail; upstream may load a cold-restored recipient even for queue-only mail (`control/api.rs:140-152`). Both preserve passive semantics: no new turn starts.
- Active Alpha MAv2 uses `interrupt_agent` and host controls rather than advertising V1 `close_agent`/`resume_agent`; `followup_task` performs retained relaunch. Historical dispatch remains readable.
