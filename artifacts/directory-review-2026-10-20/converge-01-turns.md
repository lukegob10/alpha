## Material differences and smallest next steps

1. **P2 partial capability: recovery after semantic output is restricted to the audited early read subset.** A `src/core/agent/CommittedHistoryRecoveryPolicy.ts:47` requires equal call/reservation/dispatch counts, and `:63` requires every original read result to be durably settled. A `src/core/task/Task.ts:16035` caps that early lane at four calls and `:16045` closes it on a non-audited read/mutation. Consequently, a retryable interrupted response with complete calls outside that subset can pause rather than continue from history. U `codex-rs/core/src/session/turn.rs:2973`, `:3373`, `:1763` joins accepted effects and reconstructs the retry from current history. This is a conservative implementation choice that preserves Alpha's effect boundary; it must not be repaired by allowing unsafe mutation replay. Smallest next step: add an integration fixture with five emitted complete read calls followed by a retryable disconnect; assert original durable receipts, the fifth call's known unexecuted state, and no replay, then assess whether that reconciled batch can safely qualify for a new history continuation. Mutation recovery requires a separate effect-settlement design and proof that no indeterminate effect is replayed.

2. **P3 convergence divergence: successful empty/reasoning-only responses are treated as failed/incomplete work.** Alpha's missing-output recovery is explicit (A `src/core/task/Task.ts:17873`, `:17909`, `:17925`), while upstream accepts the successful terminal response even with no final text (U `codex-rs/core/src/session/turn.rs:3183`, `:724`; U `codex-rs/core/tests/suite/stream_error_allows_next_turn.rs:45`, `:133`). A provider that intentionally ends with a nontext item can therefore cause another request or a resume boundary in Alpha. Smallest repair: distinguish an explicit successful provider terminal event from a transport that merely reaches EOF; trust the former when it does not require continuation, retain bounded empty recovery for the latter. Add fixtures for explicit empty completion, reasoning-only completion, empty EOF, and `end_turn=false`. This is lower priority than preserving deterministic receipt settlement.

An initially suspected settings gap was rejected after inspecting the upstream active-settings implementation and Alpha's activation callers. U `codex-rs/core/src/session/step_activation.rs:229` and `:375` explicitly allow admitted next-step model changes; A `src/core/webview/AlphaProvider.ts:2645` applies profile edits to the task only on the activating path. Alpha's profile activation differs from an ordinary future-turn settings write, so it is not fair to score that as missing convergence. Upstream's feature flag and append-only model-switch instruction representation are implementation/rollout details outside this turn-capability score.

None of these differences justify copying upstream Rust code, adding a second runtime, changing sandbox policy, or removing Alpha's tooling. Ordinary useful model/tool turns, durable steering, terminal status handling, and in-turn completion hooks are already substantially converged.
