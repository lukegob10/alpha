## Material differences and smallest follow-ups

### 1. Low, advisory: installed permission hooks cannot issue an allow decision

**Classification: intentional divergence, directly documented in code.** Alpha explicitly says “Native approval remains authoritative; installed hooks can deny, never create a grant” (`ToolScheduler.ts:103`). The host projects hook output to `{ denied }` or `{}` (`Task.ts:4832`), and the scheduler runs that before native approval (`ToolScheduler.ts:2522`). Codex accepts both hook allow and deny (`tools/approvals.rs:483-504`).

This affects transferring a Codex hook that expects to automatically approve a reviewed operation; Alpha still requires its native decision. It does not create weaker authority. The smallest useful follow-up is to record this deliberate divergence in the maintained convergence contract. No runtime change is necessary to satisfy a roughly 90% target. If exact hook compatibility is later required, add a typed decision variant through the existing callback and define its ceiling explicitly; regression coverage should prove deny/allow/abstain, cancellation before dispatch, and that a hook cannot override explicit outside-workspace or protected-file approval requirements.

### 2. Low, advisory: optional risk-based approval reviewer has no Alpha equivalent in the inspected path

**Classification: real optional capability gap; deliberate product exclusion not verified.** Codex's `approvals_reviewer = "auto_review"` routes approvals through a separately prompted reviewer; user approval remains its default (`config/mod.rs:3898`, `approvals.rs:552`, `protocol/src/config_types.rs:180`). Alpha's automatic decisions are rule/flag/grant decisions, and unresolved requests go to the user (`Task.ts:7194`, `auto-approval/index.ts:123`). That is not the same capability.

This matters only when comparing the optional reviewer feature. The smallest implementation, if desired, is one optional reviewer adapter in the existing approval host, with the existing typed result and policy ceiling retained. Do not add a parallel scheduler or task engine. Regression tests should cover denial, reviewer cancellation/failure, human fallback policy, exact task/call identity, and attempted widening of the invoking policy.

## Accepted differences and exclusions

- Alpha permits overlap only for audited isolated command reads, approved MCP read hints, and other audited independent read descriptors. It serializes other effects and hook-bearing batches (`ToolScheduler.ts:815,996,1037,1550,1661`). Upstream shell handlers can advertise parallel support directly (`core/src/tools/handlers/unified_exec/exec_command.rs:135`) and use a shared/exclusive runtime gate. Alpha's narrower scheduling is required by its extension policy; increasing shell-write concurrency is not a recommended convergence change.
- Codex Code Mode's JavaScript tool composition is present upstream but `UnderDevelopment` and disabled by default (`codex-rs/features/src/lib.rs:1198-1201`). It was not counted as missing default-runtime parity in this slice. A feature-inventory score including experimental features would need a separate denominator.
- Sandbox architecture, terminal/PTY implementation details, provider wire encoding, child-agent lifecycle, and whole-product tool inventory were outside this assigned slice. Alpha's built-in browser, tickets, skills, and scheduled work were not treated as divergences simply because they are extension additions.
