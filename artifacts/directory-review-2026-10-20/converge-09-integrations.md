## Material gaps

### P2: managed OAuth MCP servers require external/manual authentication

**Trigger:** A user adds a streamable HTTP MCP server that needs OAuth authorization or refreshes an expired access token. Alpha passes configured headers into `StreamableHTTPClientTransport` (`McpHub.ts:882`) but does not provide an OAuth client/provider. Upstream explicitly supports stored credentials, discovery, refresh, issuer binding, and recovery. This is ordinary third-party MCP interoperability, not a requirement to duplicate Codex's private hosted Apps.

**Smallest complete direction:** Add one MCP-owned auth adapter using the existing SDK and VS Code secret storage/URI callback facilities; supply it to the existing HTTP transport. Keep login a host/user operation, share the existing connection owner, and avoid putting credentials into task history or webview state. Preserve static-header servers.

**Regression coverage:** An isolated HTTP fixture requiring authorization, fresh authorization, expired-token refresh before initialize, 401 during a call, cancellation, and issuer mismatch. Upstream examples: `codex-rs/rmcp-client/tests/streamable_http_oauth_tool_call.rs:44`, `streamable_http_oauth_startup.rs:257`, `:647`.

### P2: standard MCP elicitation is unavailable

**Trigger:** A connected MCP tool needs a user-provided field or URL authorization through `elicitation/create`. Alpha advertises no elicitation capability (`McpHub.ts:777`) and has no inbound request handler. A conforming server therefore cannot offer that workflow; a server that sends it anyway gets unsupported-method behavior. Alpha's own tool approval dialogs do not implement this server protocol.

**Smallest complete direction:** Add one MCP request-handler bridge into the existing task/session interaction path. Preserve the originating task and call ID, validate supported forms/URLs, propagate cancellation/abandonment, bound concurrent prompts, and never let a server broaden tool approval authority. Advertise only the modes implemented. This can extend the existing shared harness rather than creating an MCP task loop.

**Regression coverage:** Root and managed-child form input; user decline/cancel; URL-only prompt; originating task cancellation; disposal with a pending prompt; unrelated background task routing; no credential contents in telemetry. Upstream examples: `codex-rs/core/tests/suite/mcp_subagent_elicitation.rs:85`, `:91`; `codex-rs/rmcp-client/src/rmcp_client.rs:1772`.

## Extension additions and intentional differences

- **Tickets:** Native Ticket tools enter `ToolRegistry` (`src/core/tools/ToolRegistry.ts:943`). Ticket work calls the same `AlphaProvider.createTask`, persists the ticket/task association before `task.start()`, and aborts an unstarted task if association fails (`src/services/tickets/TicketTaskLink.ts:52`, `:63`, `:75`). Concurrent launches are deduplicated and locked. This is a shared-harness addition, not convergence debt.
- **Scheduled agent work:** `src/services/scheduled-tasks/ScheduledTaskService.ts:539` creates a background task through `AlphaProvider.createTask`, sets its captured profile/approval mode, persists admission metadata, then calls `alphaTask.start()` after the admission write. Command-only schedules use the separate established command utility rather than a parallel model runtime. Existing terminal-durability tests cover publication failure and repeated terminal events (`__tests__/ScheduledTaskService.terminal-durability.spec.ts:157`, `:248`, `:358`). These tests were inspected, not run by this reviewer.
- **Browser and HTML:** Browser schemas/execution share the registry (`ToolRegistry.ts:1049`), feature-detect the host catalog (`src/services/browser/VSCodeBrowserTools.ts:17`), invoke `vscode.lm.invokeTool`, and dispose cancellation state (`:101`, `:137`, `:165`). The lazy HTML viewer is a presentation adapter (`src/core/webview/html-document/index.ts:10`, `:46`); canonical task transcript delivery owns automatic opening (`AlphaProvider.ts:3302`). Their UI differs appropriately from a terminal client. No exact-host runtime assertion was made.
- **JSON patch transport:** Alpha's provider-neutral function schema carries `{patch}` (`src/core/prompts/tools/native-tools/apply_patch.ts:44`) while upstream supports a grammar-constrained freeform tool (`apply_patch_spec.rs:8`). Alpha preserves/projections existing freeform patch history at `src/api/transform/tool-history.ts:92`. Treat this as a provider adapter difference, not a missing filesystem capability.
- **Audio:** Alpha intentionally emits an explicit unsupported placeholder (`UseMcpToolTool.ts:373`), consistent with its current shared text/image input contract; upstream can preserve audio for models declaring audio input (`mcp_tool_call.rs:968`). This is an optional modality limitation, not silently successful processing. If Alpha adds audio-capable providers, extend the canonical result/input contract before claiming audio parity.
- **Connection refresh:** Upstream retains a superseded connection for admitted calls (`codex-rs/core/tests/suite/mcp_refresh_cleanup.rs:133`, `:246`). Alpha validates captured connections immediately before dispatch and can close replaced connections. This is a stricter fail-closed lifecycle choice; no late-response bug was established in this review. Do not infer that missing lifecycle signal composition alone proves a failing runtime when the SDK closes pending requests.
