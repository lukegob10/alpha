## Material gaps

### P1: PTY hard timeout does not establish the termination it reports

**Trigger:** A foreground Code task uses `exec_command` with `tty: true`, has a configured nonzero command timeout, and runs a process that ignores Ctrl-C. The configured hard-timeout path calls `process.abort()`, which merely sends an interrupt for the VS Code transport. No physical-exit wait or stronger termination occurs in that adapter. The foreground result can say “The command was terminated” at `ExecuteCommandTool.ts:2059` while the shell command continues. Mutation debt is conservatively retained when exit is unknown (`:1965-1973`), but that does not stop the process or make the text truthful.

**Minimal remedy:** Distinguish `interrupt()` from a hard stop in the existing terminal adapter contract. A hard timeout should perform a bounded graceful interrupt, then terminate/dispose the exact owned terminal/process through the VS Code adapter and wait for a reliable closure signal. On failure, report unconfirmed termination and preserve ownership/debt. Do not weaken task/workspace ownership or recreate execution infrastructure.

**Regression:** Use a controlled PTY whose interrupt is accepted but produces no exit event. Advance the host timeout, prove the hard-stop adapter is invoked for the original process only, and ensure termination success is withheld until closure; test rejection/unconfirmed closure and a late exit exactly once. The existing unknown-outcome fixture at `src/core/tools/__tests__/ExecuteCommand.lifecycle.spec.ts:21-60,456-485` is the nearest extension point. Physical ignored-SIGINT behavior was inferred from code; no live PTY was launched in this review.

### P2: Finished-session pruning does not bound live terminal growth

**Trigger:** Repeated commands yield to the background without ending. The 64-session constant constrains completed retained records, not live sessions/terminals. Serial tool scheduling limits simultaneous launch operations but does not limit the number of already-yielded processes. Each busy prior terminal forces `TerminalRegistry.getOrCreateTerminal()` to allocate another. Upstream applies pressure to the total process store and terminates the pruned original process.

**Minimal remedy:** Add a task/host admission budget at the existing registry/command owner, count already-running and in-admission commands, and reject or queue new launches when the budget is exhausted. Prefer explicit admission backpressure over silently killing an active user process; document that deliberate safer difference from upstream LRU eviction. Release capacity only on owned physical closure, including cancellation and failed admission.

**Regression:** Admit 64 fake long-lived processes, then attempt a 65th and verify the chosen bounded policy, stable ownership, no leaked terminal reservation, and capacity recovery after a controlled exit. Include simultaneous pending admissions so the check cannot race. Source-verified capacity gap; no stress benchmark was run.

### P3: `write_stdin` ends a requested collection window on its first output

**Trigger:** Poll a running process with a 5-30s requested wait while it produces small bursts. Alpha's `waitForCommand` returns on the first `output_available` or immediately for preexisting unread output. Current Codex collects successive bursts until the requested deadline or completion. This is an observable transport contract difference; any effect on model round trips is plausible but unmeasured.

**Minimal remedy:** Decide and document whether early wakeup is an intentional Alpha responsiveness choice. For closer convergence, add a deadline-based aggregation mode in the existing command wait/receipt owner, preserving cancellation, bounded buffers and safe finalization. The UI can continue streaming output while the tool result aggregates.

**Regression/measurement:** Fake-clock process emits at 100ms, 200ms, then exits at 300ms. A 5s poll should return once at exit with both bursts under convergence semantics; a non-exiting process should return once at deadline. Compare the same scripted burst workload before/after for returned tool calls and wall time before making a latency claim. The current early-wakeup regression is `ManageCommandTool.spec.ts:53-76`.

## Intentional Alpha differences, no score deduction

- **Terminal interactions remain serial:** Upstream permits `write_stdin` in parallel across sessions (`codex-rs/core/src/tools/handlers/unified_exec/write_stdin.rs:46-47`; per-process lock `process_manager.rs:902-917`; explicit test `codex-rs/core/tests/suite/unified_exec.rs:4023-4083`). Alpha marks session controls serial/workspace (`src/core/tools/ToolRegistry.ts:691-717`) and only admits audited isolated command reads to parallelism. Root `AGENTS.md` explicitly requires terminal interactions to serialize. Honor that safety contract; this is not a must-fix convergence issue.
- **Task cancellation is stronger:** Current Codex intentionally preserves long-running unified-exec sessions after ordinary `Op::Interrupt` (`codex-rs/core/tests/suite/unified_exec.rs:3010-3093`), with separate background cleanup/shutdown. Alpha stops task-owned processes before finalizing task cancellation (`src/core/task/Task.ts:9846-9930`), and retains handles after failed stop (`src/integrations/terminal/TerminalRegistry.ts:308-318`). This is a deliberate lifecycle/protection difference, separate from the hard-timeout defect above.
- **Alpha adds artifact reads and mutation bookkeeping:** `write_stdin` accepts task-owned artifact reads (`ToolRegistry.ts:369-381`); receipt commit/release prevents failed delivery from losing unread output (`ManageCommandTool.ts:169-232`). Native extension approvals, workspace mutation ownership, strict Plan inspection restrictions, and PTY availability only in foreground Code are retained. Their absence from Codex's exact API shape is not penalized.
- **Shell selection remains host-owned:** Alpha's schema exposes command/cwd/tty/yield/output budget (`src/core/prompts/tools/native-tools/execute_command.ts:29-79`), while Codex also exposes `shell`/`login` (`codex-rs/core/src/tools/handlers/unified_exec.rs:26-35`). No full shell-environment equivalence claim is made here; absence of those optional parameters is not treated as a required implementation identity.
